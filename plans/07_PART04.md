## P04-S04 — CooPre

**File:** `drivex/scenes/part04/p04_s04_coopre.py`
**Class:** `P04S04CooPre`
**Background:** WHITE
**Duration:** ~80s

### What
CooPre — cooperative pretraining via multi-agent masked LiDAR reconstruction. *"When I can't see something, ask other agents."* Result: 50% labels → 100% baseline performance. +4% AP at full data.

### Reviews
- Review 2: "align cái grid map sao cho nó center của 2 cái center kia theo chiều ngang, để cái mũi tên nhìn nó đều"

### Critical fix
The grid map must be centered horizontally between the two source agent centers, so arrows from each agent point evenly. Use:
```python
grid_map.move_to([midpoint_of_agents_x, grid_map_y, 0])
```

### Visual blueprint
```
       CooPre — pretraining without labels

   Agent A LiDAR     Agent B LiDAR
       ●●●               ●●●
        │                 │
        └────────┐ ┌──────┘
                 ▼ ▼
            ┌───grid───┐                       ← horizontally CENTERED
            │ ░░ █ ░░  │  ← masked voxels
            │ █ ░░ █   │
            │ ░░ █ █   │
            └──────────┘
                 │
                 ▼
        ┌── Reconstruct masked ──┐
        │ "fill in what I can't  │
        │   see using B's data"  │
        └────────────────────────┘

       Self-supervised → no annotation needed

       Result:
        • 50% labels → matches 100% baseline
        • 100% labels → +4% AP
```

## P04-S05 — Multi-Task Conflict

**File:** `drivex/scenes/part04/p04_s05_multi_task_conflict.py`
**Class:** `P04S05MultiTaskConflict`
**Background:** WHITE
**Duration:** ~60s

### What
Why multi-task multi-agent training is hard:
- Init sensitivity (architecture too complex)
- **Gradient conflict** between tasks (vectors pulling opposite directions in weight space)

### Reviews
- Review 1: "cái chỗ gradient conflict thì vẽ cái 3d coord, vẽ một cái mặt phẳng gì đó vẽ mấy vector ngược hướng nhau trên đó nó trực quan hơn á."
- Review 3: "box multiframe gì đó ở cảnh đầu tăng chiều rộng lên, chú ý coi chừng overlap mũi tên"

### Critical fixes
1. **3D coordinate visualization for gradient conflict**: 3 axes, plane, vectors pointing opposite directions on the plane. Use `ThreeDScene` if needed, or fake 3D in 2D using isometric drawing.
2. **Multi-frame box widen** — text overflowing.

### Visual blueprint
```
       Multi-task multi-agent — why training is hard

   ┌── Architecture is complex ──┐
   │   Multi-frame             ─┘
   │   Multi-agent              │
   │   Multi-task               │
   │   → init very sensitive    │
   └────────────────────────────┘

   Gradient conflict (3D coord viz):

         z (weight space)
         │
         │       ↗ Detection ∇
         │      /
         │    ╱
         └─────────→ x
        ╱
       ╲ ↘ Prediction ∇
   y    ╲
         (vectors ANTI-PARALLEL on the plane)

   "Improving one task degrades another."
```

### Animation flow

## P04-S08 — QuantV2X

**File:** `drivex/scenes/part04/p04_s08_quantv2x.py`
**Class:** `P04S08QuantV2X`
**Background:** WHITE
**Duration:** ~70s

### What
QuantV2X — first fully-quantized V2X system:
- Model-level: FP32 → INT8 (4× memory reduction).
- Communication-level: features → low-bit codebook (300× compression).

### Reviews
- Review 1: "cái int8 nó đè hẳn lên FP32 luôn, nếu bạn làm hiệu ứng shrink thì làm lại tại vì nó nằm chính giữa cái dải màu đỏ luôn ấy. chỗ distribution thì cái chữ vàng đang overlap với chữ đỏ ở 1 phần góc trái trên của chữ đỏ"
- Review 2: "3 cái bullet tick point ở đầu đang bị overlap với fp32, move nó xuống dưới một xíu để tránh overlap"

### Critical fixes
1. **INT8 box overlaps FP32 box**: when shrinking FP32 → INT8, place INT8 NEXT TO (not on top of) FP32. Use `Transform` with explicit final position SHIFTED.
2. **Yellow text overlaps red text** in the distribution part: position labels with explicit `next_to` and adequate buff.
3. **3 bullet points at top overlap FP32 box**: move bullets DOWN.

### Visual blueprint
```
       QuantV2X — fully quantized V2X

   First system to quantize at TWO levels:
   ✓ Model: FP32 → INT8                       ← bullets, NOT overlapping FP32 box
   ✓ Comm: BEV features → codebook (300× ↓)
   ✓ Edge-deployable, accuracy preserved

   Model:                   Communication:

   ┌─FP32─┐                 ┌─FP32─features────┐
   │ ████ │                 │ █████████████████│
   │ ████ │                 └──────────────────┘
   │ ████ │ → │INT8│ ←      ┌─codebook─┐
   │ ████ │     ↑           │ ▌        │   300×
   └──────┘     ↑           └──────────┘
   shrink to  side-by-side, NOT on top
   1/4 size  
```

### Animation flow
1. Header + 3 bullets at TOP-LEFT (positioned so they don't overlap mid-canvas)
2. Model section: FP32 box on left
3. INT8 box appears to the RIGHT of FP32 (smaller); arrow indicates conversion
4. Communication section below
5. FP32 features bar on left, codebook bar on right (300× smaller)
6. End
